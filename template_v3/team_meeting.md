# [例会概况]
[一段话概括本次例会（一段写完，约 250–400 字）：① 参会成员或部门（姓名优先，没人名写部门/角色，人数照原文）② **为什么开这次会**（当前阶段或由头，原文有才写）③ 主线议题（把议题名列出来，**每块用一句话交代谈到什么程度：已定 / 待定 / 仅同步**，不展开任务明细）④ **整体态势**（哪些顺利、哪些卡住或延期、是否按计划，一两句）⑤ 结论与下一步方向（没有结论就写「本次以同步为主，未形成明确结论」）⑥ 原文有关键数字或时间节点时选 1–3 个作锚点（人数、任务数、节点日期、延期天数），原文没有则不强求、不补写；各任务的进展与分工明细归 [工作进展]（谁做了什么、做到什么程度、下一步与时限）、需要别人配合的事归 [协作需求]，**本栏只到「议题级主线 + 态势」，不写任务级明细**；内容够就写到接近 400 字——低于 250 字说明没交代清「为什么开、谈成什么样、态势如何」]

# [工作进展]
[**按成员或模块分组呈现**（每组一行 `## 成员/模块名`，每组 2–5 条；**不要在栏内再写一个与栏名同名的 `## 工作进展`**；同一模块/成员下并列的多个任务各占一条），**每条写成 `- **任务名**：进展；下一步…；时间节点…`**（约 500–900 字）——四要素（谁、做了什么、做到什么程度、下一步）齐全，信息少的也要写清进展，**不要只写状态或半句碎片、不要一句一条**（同一次修改的连续动作合并成一条）；**一个任务讲不完就用缩进子条 `  - ` 拆开；原文提到的具体任务、数字、时间节点都要落进对应条目**；状态（✅已完成 / 🔄进行中 / ⛔阻塞）在任务名后标一次；关键阻塞、延期节点与任务名、版本号、工单号各用 **具体内容** / `具体内容` 标注；**本栏只写"已经做了什么、到什么程度"——会上定下来的分工、责任人与时限归 [决定与待办]，两栏不重复**]

# [决定与待办]
[只写会上**定下来的事**（不是讨论过程，约 150–350 字）：拍板或达成一致的决定（带口径与依据）、明确的行动项（谁、何时前、做什么）、当场作出的承诺与任务分配；一条一个事项、`- ` 一条一行（`- **事项**：内容`），同一次决定的多个动作合并成一条、需要拆分时用缩进子条 `  - `；**责任人与时间节点照原文写，原文没给就只写事、不留空位**；**已在 [工作进展] 条目里写过的"下一步"、已在 [协作需求] 写过的依赖，本栏都不重复**；没有拍板或分工就写「未提及」（只讨论、未定下来的事项归 [待确认与风险]）]

# [协作需求]
[列出成员间提出的协作请求、跨人/跨组依赖项及需要支持的事项（约 150–300 字），写清提出方与配合方；**只写需要别人配合的事（谁需要谁做什么、何时前），已在 [工作进展] 写过的进展不复述**；原文提到的跨人依赖一条不落；同一任务沿用[工作进展]里的名称，不要换称]

# [待确认与风险]
[只写**未决与异常**（约 100–250 字）：尚未议定或需要再确认的事项、会上提出的不同意见与分歧、明确的阻塞与延期、需要请示或等外部条件的事项；一条一个事项、`- ` 一条一行（`- **事项**：内容`——写清卡在哪、在等什么、影响什么），同主题的多条合并成一条；**只写原文出现的未决与风险，不替团队预判**（原文只是"讨论过"不算风险）；**不要写「原文未提及…」这类说明句**；没有这类内容就写「未提及」]
