# 模板注册表（本目录即权威源 · v3）

`template_v3/*.md` 是**运行时的模板注册表**：服务通过 `app/config.py::template_registry()`
**直接读这些文件**，没有 YAML、也没有第二兜底源。文件名（不含 `.md`）就是模板 ID，
也是接口 `extra.template` 可填的**英文名**。

## 1. 请求里怎么填 `extra.template`

只接受两种写法（英文名大小写不敏感、可带 `.md`）：

- **md 英文名**：`project_progress`（= 文件名）；
- **中文名**：`项目进度会`（= 文件第一行 `# 中文名`）。

内部契约键 `{场景ID}_{模板ID}`（如 `meeting_minutes_project_progress`）与其它串一律 400。
30 个英文名与 30 条中文名各自唯一、互不冲突。

## 2. 文件结构（固定，改模板时保持）

```markdown
# 项目进度会                       ← 中文名（文件头，不进 format）

<!-- requirement
写作要求（只写底线：不得丢失 / 篡改 / 臆断 / 失真）
-->                              ← requirement 注释块，单独解析

# [项目概况]                      ← 以下为 format 正文
[一段话概括项目阶段、整体健康度及本次进度会的主要内容]
…
```

运行时把文件拆成三部分：`name`（第一行标题）、`requirement`（注释块）、`format`（其余正文）。
`format` 里方括号是占位说明，表格里的 `| … |` 行是待填数据行。

## 3. 模板写法公约（新增/修改模板一律遵守）

1. **`requirement` 只写底线，不写形态**：可以写"不得丢失 / 不得篡改 / 不得臆断 / 不得失真"；
   **不要**写"逐条 / 分项 / 不得合并 / 保留原始语义"这类**产出形态**词——形态（栏目、合并、篇幅）
   由 `format` 与尺寸规则决定，否则两份文本会互相打架。
2. **兜底写成祈使式，禁用条件句**：写"缺项直接写「无」"，**不要**写"若某项不存在则填写「无」"——
   条件句会被模型复述进正文（曾出现 `以上改进计划均未明确责任人和时间，填写"无"。`）。
3. **同类/对立信息用"可归并、不可抹平"**：允许合并同类表述，但立场、结论口径与关键信息点不得被抹平。

> 冲突裁决（写在公共规则里，改模板时不必重复）：**篇幅上限是硬约束**；
> 在不超过上限的前提下优先保真（不删事实、不改口径与人名数字），其次保结构（栏目齐全）。

## 4. 怎么改模板

直接编辑对应的 Markdown 文件，并保持第 2 节的固定结构。修改后启动服务，
通过 `/docs` 提交一条使用该模板的请求，检查生成结果和模板门禁提示。

新增模板：在本目录放一个 `{id}.md`（结构见第 2 节），并在 `app/config.py` 的
`TEMPLATE_SCENARIO` 里登记 `{id} → 场景ID`（否则不会被注册，`extra.template` 会 400）。
