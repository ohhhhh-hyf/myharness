# 小艺建议与主动服务

> "小艺建议"代表的是小艺从"你问我答"走向"主动服务"的一类能力：
> 基于时间、地点、场景与使用习惯，在合适的时候把合适的服务卡片/建议推到你面前。

## 一、能力定位

| 维度 | 说明 |
| --- | --- |
| 形态 | 桌面/负一屏的**建议卡片**、系统内**主动提醒**、控制中心快捷入口 |
| 数据基础 | 端侧行为习惯、时间地点、日程、设备状态等（遵循隐私设计，见安全文档） |
| 分发机制 | 依托**意图框架**与 Agent 分发体系，把服务在合适场景触达用户 |
| 与智能体关系 | 智能体广场的智能体按"用户需求与意图"公平分发（2025-2026 体系） |

## 二、典型主动服务场景

- **通勤**：根据习惯推送出行时间提醒、路况变化；
- **日程**：会议前提醒、待办到期提醒（可与小艺慧记提取的待办联动）；
- **服务入口**：近期使用的服务、跨应用任务的相关入口；
- **设备协同**：多设备场景下把服务分发到最合适的设备（详见《语音交互与唤醒机制》中的技能分发规则）；
- **记忆驱动**：基于小艺帮记中存储的信息（证件、订单、地址）在需要时主动提示。

## 三、主动服务的两种新形态（2025-2026）

前述场景卡片是"**定时聚合 + 场景触发**"；近两年主动服务分化出两条更具体的新形态：

| 形态 | 触发方式 | 典型载体 | 详见 |
| --- | --- | --- | --- |
| **小艺简报** | 每天 6:00–24:00 定时聚合 | 桌面 2×2 / 2×4 建议卡片 | 《小艺简报与信息聚合》 |
| **伴随式 AI** | 在具体任务界面**双击小艺导航条** | 购票页、出行途中、网页长文 | 《小艺伴随式 AI 与出行场景》 |

**小艺简报**把待办、通知摘要、日程、天气、睡眠、回忆、播客聚合成一张卡片，
可**一键语音播报**——本质是"把一天要关心的事一次性推到你面前"。

**伴随式 AI**则相反：不做定时推送，而是在你**正在做某件事**时（如刚买完票）
识别屏幕内容并推送下一步操作的卡片——本质是"在任务链路里替你走下一步"。

> 三者的关系：**建议卡片**是基础形态，**简报**是它的定时聚合版，
> **伴随式 AI**是它的场景即时版。三者的开关与隐私控制路径不完全相同。

## 四、意图框架：主动服务的技术底座

- **300+ 服务**通过意图框架接入小艺（HDC 2024 数据）；
- HMAF 2.0 提出"**意图即服务**"：用户表达意图，系统自动选择并调度对应服务；
- **服务分发排序**：设备与技能匹配度、使用习惯、置信度（多设备场景）。

## 五、用户如何用好主动服务

1. **保持基础信息开启**：日程、位置、使用习惯等（按需授权）；
2. **善用全量模式**：应用服务模式切为全量模式，解锁跨应用建议与执行；
3. **管理通知与隐私**：在设置中调整个性化推荐、改进计划等开关；
4. **主动反馈**：不需要的建议可忽略/关闭，系统会据此调整。

## 六、边界与注意事项

- 主动服务需要一定数据基础，**默认关闭个性化选项时体验会明显减弱**；
- 隐私敏感数据（通讯录关系链等）默认受限，需显式授权；
- 部分"网络流传的隐藏口令/彩蛋"已下线，主动服务的具体入口以当前系统版本为准；
- 建议类内容不做敏感决策，重要事项请以正式渠道确认。

## 七、常见问题

| 问题 | 解答 |
| --- | --- |
| 为什么看不到建议卡片？ | 检查是否关闭了个性化推荐/通知，或数据授权不完整 |
| 建议会泄露隐私吗？ | 遵循"数据最小化、端侧处理、透明可控"原则，可在隐私设置中管理 |
| 和"小艺帮记"什么关系？ | 帮记存储的信息可作为主动服务与问答的数据来源 |
| 能关掉主动服务吗？ | 可以，在设置中关闭个性化推荐或对应通知 |
| 小艺简报和建议卡片是一回事吗？ | 简要是**建议卡片的一种**（定时聚合版），需手动添加卡片，详见《小艺简报与信息聚合》 |
| 伴随式 AI 和主动服务什么区别？ | 伴随式 AI 是**在任务界面即时触发**（双击导航条），主动服务偏向定时/场景推送 |
| 简报怎么关掉？ | 长按简报卡片 >"不再推荐此卡片"（整体），或"管理卡片 > 简报开关"（单项） |
