在终端里，把代码任务
交给一个会自己动手的助手

myharness（XiaoYi）是一个运行在终端中的 AI 编程助手。它在你的真实项目目录里工作， 通过大模型驱动工具调用来读代码、检索、改文件、跑命令并验证结果 —— 内置权限矩阵、 MCP 扩展、子智能体、长期记忆与上下文管理。

四个让它真正好用的设计

1条命令

任意目录可用

装好后在任何文件夹敲 xiaoyi 即可启动，项目根自动取当前目录 —— 不需要先 cd 到某个固定位置。

63个 MCP 工具

开箱即用

内置 5 台基于 uvx 的 MCP 服务器：文件系统、网页抓取、浏览器自动化、PDF 处理、Excel 表格，无需 Node 环境。

6种权限模式

可控的自主性

读操作放行、写文件与执行命令按模式处理；再叠加用户级/项目级/本地级三层规则文件，精细到命令模式。

8大能力模块

不是一个裸壳

权限矩阵、路径沙箱、危险命令检测、子智能体、记忆、上下文压缩与回溯、技能与钩子、RAG 知识库。

功能总览

八项核心能力

从交互界面到上下文管理，每一层都为"在真实项目里可靠地完成任务"服务。

终端原生界面

基于 Textual 构建，支持流式输出、工具调用可视化、命令补全与用法提示；退出后对话内容保留在终端回看区。

多模型接入

支持 Anthropic、OpenAI 以及任意 OpenAI 兼容端点（DeepSeek、GLM、Qwen、本地推理服务），三种协议自由切换。

完整工具体系

文件读写、目录遍历、内容检索、命令执行等内置工具，配合权限矩阵、危险命令检测与路径沙箱形成多层防护。

MCP 扩展

作为 MCP 客户端接入 stdio 与 Streamable HTTP 两类服务器，其工具自动注册进工具表（命名 mcp__<server>__<tool>）供模型调用。

子智能体协作

内置 Explore（只读检索）、Plan（方案规划）、Verification（结果验证）与 general-purpose 四类子智能体，也支持用 Markdown 定义项目级/用户级自定义子智能体。

记忆系统

自动从对话中提炼要点形成长期记忆，后续请求按相关性检索注入；记忆以可读的 Markdown 存放在项目与用户两级目录。

上下文管理

工具结果落盘与剪枝、超限自动压缩（摘要替换历史）、会话持久化，以及文件级回溯（rewind）。

可扩展机制

技能（Skills）、生命周期钩子（Hooks）与斜杠命令体系，均支持项目级与用户级扩展；另有 RAG 知识库与团队协作模式。

安装

三种装法，任选一种

共同前提：Python ≥ 3.11 与 uv。uv 是 Rust 写的单文件工具，装它本身就是一条命令。

① 一键脚本（Windows 推荐）

下载并双击运行，脚本会自动：检查/安装 uv → 克隆仓库 → 按 uv.lock 钉住依赖版本 → 安装全局 xiaoyi 命令 → 写好用户级配置模板。装完新开终端即可使用。

下载 myharness-setup.cmd

若提示找不到命令，执行一次 uv tool update-shell 并重开终端。

② 从源码安装（开发推荐）

克隆仓库后，用仓库自己的虚拟环境运行 —— 这套环境由 uv sync 按 lock 维护，改代码立即生效。

git clone https://github.com/ohhhhh-hyf/myharness.git
cd myharness
uv sync
uv run xiaoyi

③ 装成全局命令，之后任意目录可用

核心是"生成一个叫 xiaoyi 的可执行文件并放进 PATH"，同时一份用户级配置让它在任何目录都能读到模型设置。

1

同步依赖并导出锁定的版本清单

uv 的 tool install 默认不读 uv.lock，会解析到最新版依赖；导出成清单后，安装时按清单钉住版本。

cd path\to\myharness
uv sync
uv export --format requirements-txt --no-dev --no-emit-project --no-hashes -o "%USERPROFILE%\.xiaoyi\tool-constraints.txt"
2

安装全局命令

--editable 让命令读取仓库源码（改完即生效），-c 让依赖版本严格按上一步的清单。

uv tool install --editable . -c "%USERPROFILE%\.xiaoyi\tool-constraints.txt"
uv tool update-shell        # 提示 .local\bin 不在 PATH 时执行，然后重开终端
3

写一份用户级配置

配置查找顺序为「用户级 → 当前目录项目级 → 项目本地级」，且只看当前目录、不向上找父目录；缺了用户级配置，在别的目录启动会直接报错退出。

mkdir "%USERPROFILE%\.xiaoyi" 2>nul
notepad "%USERPROFILE%\.xiaoyi\config.yaml"

最小配置（%USERPROFILE%\.xiaoyi\config.yaml）：

providers:
  - name: deepseek
    protocol: openai-compat
    base_url: https://api.deepseek.com
    model: deepseek-v4-flash
    api_key: ""            # 留空则读环境变量 OPENAI_API_KEY
permission_mode: default

其他系统（macOS / Linux）：

curl -LsSf https://astral.sh/uv/install.sh | sh
git clone https://github.com/ohhhhh-hyf/myharness.git
cd myharness && uv sync
uv export --format requirements-txt --no-dev \
  --no-emit-project --no-hashes -o ~/.xiaoyi/tool-constraints.txt
uv tool install --editable . -c ~/.xiaoyi/tool-constraints.txt
配置

配置说明

配置文件按「用户级 → 项目级 → 项目本地级」逐层合并，后者覆盖前者；MCP 服务器按名字合并，钩子叠加。

providers · 模型提供方

字段必填说明
name是提供方标识
protocol是anthropic / openai / openai-compat
base_url是接口地址，兼容端点填自己的服务地址
model是模型名
api_key否留空则回退到环境变量（anthropic → ANTHROPIC_API_KEY，其余 → OPENAI_API_KEY）
context_window否上下文窗口；0 或缺省时尝试自动解析

permission_mode · 权限模式

读类操作始终放行；写文件与执行命令按模式处理，也可启动时用 --mode 临时覆盖。

模式读取写文件执行命令
default放行询问询问
acceptEdits放行放行询问
plan放行询问询问
bypassPermissions放行放行放行
dontAsk放行放行放行
custom询问询问询问

mcp_servers · MCP 服务器

mcp_servers:
  # 项目自带的文件系统 server（uvx 拉起，不依赖 Node）
  - name: filesystem
    command: uvx
    args: ["fsext-mcp-server", "--lock-root", "."]
  # 网页抓取
  - name: fetch
    command: uvx
    args: ["mcp-server-fetch"]
  # Streamable HTTP 远程服务
  - name: remote
    url: https://example.com/mcp
    headers:
      Authorization: Bearer ${MCP_TOKEN}   # 支持环境变量展开

MCP 工具自动注册进工具表，命名约定为 mcp__<server>__<tool>（双下划线）， 可用 /mcp 查看连接状态与各服务器的工具数。

默认配置里的五台服务器共提供 63 个工具：filesystem 22、excel 25、playwright 8、pdf 7、fetch 1。 Windows 上若改用 npm 版服务器，命令需要写成 npx.cmd（裸 npx 会报 WinError 2）。

playwright 需要浏览器二进制：uvx --from playwright playwright install chromium。

hooks · 生命周期钩子

事件用途
session_start会话开始
turn_start每轮开始
pre_tool_use配合 reject 可拦截工具调用
post_tool_use工具执行后
file_change文件变更
error / shutdown出错 / 退出

钩子动作类型包括 command、prompt、http、agent； pre_tool_use 可拦截，其余事件可声明 async 异步执行。

其他开关：

  • enable_fork —— 子智能体继承当前对话上下文
  • enable_verification_agent —— 启用内置验证子智能体
  • enable_rag —— 本地 RAG 知识库（检索证据注入 + KnowledgeSearch 工具）
  • teammate_mode / enable_coordinator_mode —— 团队协作与协调者模式

按键作用

命令行与交互约定

xiaoyi                        # 交互式界面
xiaoyi -p "解释这个项目的目录结构"  # 单次执行并输出
xiaoyi --mode acceptEdits      # 临时覆盖权限模式
  • 输入以 / 开头即为命令，例如 /mcp 查看 MCP 状态、/status 查看当前会话信息
  • 输入 @ 可引用项目内文件路径
  • 图像输入：把图片拖入终端或复制后粘贴（终端插入的是路径），提交时自动识别为图片附件；支持 png / jpg / jpeg / gif / webp，单张上限 5 MB
  • 路径与文字无需留空格，D:\a\shot.png这个报错怎么看 也能正确切分
状态目录：harness 会在启动目录下创建 .xiaoyi/，用于存放 debug.log、 sessions/（会话记录）、memories.md（长期记忆）与权限规则。 它同时也是路径沙箱的边界 —— 若该目录是 git 仓库，记得把 .xiaoyi/ 加进 .gitignore。
架构

代码结构与扩展点

主循环、TUI、工具与权限各自独立；MCP、子智能体、技能与钩子都是可插拔的扩展面。

核心

agent.py 主循环与上下文管理；app.py 终端界面（Textual）；client.py 三种协议的模型客户端。

工具与权限

tools/ 工具注册与实现；permissions/ 权限矩阵、规则引擎、危险命令检测与路径沙箱。

扩展

mcp/ MCP 客户端与工具包装；agents/ 子智能体；memory/、skills/、hooks/、teams/、worktree/。

项目级指令

在项目根放 XIAOYI.md 或 .xiaoyi/XIAOYI.md，内容会注入到每次请求；也支持 @include 引用项目内的其他文件（越界路径会被拦截）。用户级指令放在 ~/.xiaoyi/XIAOYI.md。
